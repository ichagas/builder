Pronghorn frontend redesign

Three working prototypes for the same product, each applying the same five principles differently. Every frame is live: click, commit, deploy, answer the agent. State is kept in the URL and in local storage, so reloading a frame keeps your place. See PROPOSAL.md for the reasoning and rollout plan.

A. Lifecycle Rail

Open full screen

You navigate by project phase: Define, Design, Build and Ship. Each phase shows its progress, and its tools sit inside it. A "next step" banner and a single primary action appear in the same place on every screen. Try: Build → Commit changes, then Undo. On Define, select a story to open its detail panel.

B. Next Action

Open full screen

The project opens on a ranked queue of what needs you. Each card has one main action, and its details expand inline. Answering the agent's question starts a run, and the run adds a new review card when it finishes. All tools are under "Project", grouped by task.

C. Workbench

Open full screen

One persistent workspace. A tool dock is grouped by task, and an inspector appears only when you select something. On a phone the inspector becomes a bottom sheet with three heights. An IDE-style run dock shows agent, staging and environment status everywhere. Try: select "Intake API", rename it, then press "Build this with the agent". ⌘K jumps to any tool, component or file.
