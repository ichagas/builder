Onboarding existing applications: three options

For apps that aren't built in Pronghorn but adopt its Standards: agents, skills, tools and the Assurance Mesh (Green, Yellow, Red and Blue agents, Velocity White Paper No. 07). Onboarding runs once in a sandbox, then Pronghorn keeps the Standards in sync through pull requests. Every frame is live. See ONBOARDING.md for the reasoning.

OPTION A

Connected project

Open

The same Approach 3 shell as greenfield projects. The timeline shows the Standards packs this app adopted, the flag is Onboarded, and the four phases become Review → Standards → Agents → Mesh. They run once for onboarding and again for every pack update. Repository tabs handle multi-repo and multi-stack apps.

OPTION B · CHOSEN

Assurance console

Open

Chosen, organized as Teams → Applications → Repositories. Connected apps aren't projects. They live in one organization-level console: a portfolio grid of apps × repositories × mesh agents, a timeline of merges to main with their verdicts (select one for its evidence), and a four-step onboarding wizard.

OPTION C

Standards subscriptions

Open

Pronghorn as a package registry for Standards. A repository subscribes once. pronghorn.standards.yml pins a pack, and new packs arrive as update pull requests. The timeline shows pack releases with how many repos pin each one. The four sections describe what a pack contains, per stack profile.
